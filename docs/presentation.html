CloakNDA

Confidential NDA Management Using Fully Homomorphic Encryption

A Production-Grade dApp on Zama fhEVM

The Problem

Blockchain Transparency vs. NDA Confidentiality

  • The Paradox: Blockchain is transparent, but NDAs are confidential
  • Trust Issues: Centralized intermediaries can be hacked or compromised
  • Computational Limitation: Can't perform operations on encrypted data
  • Regulatory Compliance: GDPR, CCPA require data privacy
Key Challenge: How do you store sensitive data on a public blockchain while keeping it private?

The Solution: Fully Homomorphic Encryption

Computation Without Decryption

Plaintext Data → [FHE Encryption] → Encrypted Data Encrypted Data → [Computation] → Encrypted Result Encrypted Result → [Decryption] → Plaintext Result Key insight: Computation happens WITHOUT decryption!

Why This Matters:

  • Privacy: Data stays encrypted throughout its lifecycle
  • Computation: Smart contracts can work with encrypted data
  • Verification: Results are cryptographically verifiable
  • Compliance: Meets strict data privacy regulations

Three layers working together seamlessly for encrypted NDA management

Creator Workflow

Step 1: Create NDA ├─ Title, Terms, Counterparty, Expiration Step 2: Encrypt & Submit ├─ Backend encrypts sensitive fields using fhEVM Step 3: Store on Blockchain ├─ Smart contract stores encrypted data immutably Step 4: Share & Track ├─ Creator gets NDA ID to share └─ Tracks signature status in real-time
Key Benefit: Your confidential terms are protected by cryptography, not just trust

Counterparty Workflow

Step 1: Receive NDA ID ├─ Creator shares NDA ID Step 2: Request Decryption ├─ Backend verifies counterparty address ├─ Only authorized parties can decrypt Step 3: View Decrypted Terms ├─ Backend decrypts using fhEVM └─ Counterparty sees plaintext terms Step 4: Sign & Submit ├─ Signature encrypted and stored └─ Creator notified immediately
Key Benefit: Access control is cryptographically enforced - only the right person can see the terms

Auditor Workflow

Step 1: Request Access ├─ Creator grants auditor access Step 2: View Audit Trail ├─ See all NDA operations ├─ Creation, signatures, termination Step 3: Verify Integrity ├─ Verify encrypted data hasn't been modified ├─ Confirm all operations are legitimate Step 4: Generate Report ├─ Create compliance report └─ Blockchain-verified timestamps
Key Benefit: Complete transparency for auditors while maintaining privacy for parties

Data Flow: Creating an NDA

1. Creator Input (Plaintext) ├─ Title, Terms, Counterparty, Expiration 2. Frontend Encryption └─ Sends to Backend API 3. Backend Processing ├─ Calls fhEVM Coprocessor └─ Encrypts: Terms, Counterparty, Expiration 4. Smart Contract Storage ├─ Stores encrypted data └─ Generates NDA ID 5. Audit Trail ├─ Records creation event └─ Blockchain-verified timestamp 6. Frontend Confirmation └─ Displays NDA ID to creator

Data Flow: Signing an NDA

1. Counterparty Request └─ Enters NDA ID 2. Backend Verification ├─ Retrieves encrypted NDA └─ Verifies authorization 3. Decryption (fhEVM) ├─ Backend calls fhEVM Coprocessor └─ Returns plaintext to backend 4. Frontend Display └─ Counterparty reviews and signs 5. Signature Encryption ├─ Backend encrypts signature └─ Sends to smart contract 6. Contract Update ├─ Stores encrypted signature └─ Updates status to "Signed" 7. Audit Trail └─ Records signature event
